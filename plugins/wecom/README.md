# 企业微信智能机器人插件

这个插件通过企业微信的 WebSocket 长连接接收智能机器人的消息，把单聊消息或群里 `@机器人` 的消息交给静静判断、建任务。它和其他插件一样安装、删除。

不需要公网 IP，也不需要回调 URL；主机能主动访问企业微信即可。

## 一、企业微信后台

1. 进入企业微信管理后台 → 工作台 → 智能机器人 → 新建机器人；
2. 把机器人可见范围设好；
3. 在机器人编辑页把连接方式切换为 **API 模式 → 长连接**；
4. 在机器人详情页复制两个凭证：
   - **BotID**
   - **Secret**（长连接凭证，不是企业应用的 Secret）
5. 把机器人加进目标群，或直接在单聊里使用。

> 群聊里只有 `@机器人` 的消息会推给机器人；普通群聊内容不会推。想读全部群消息只能走屏幕捕获或企业会话存档。

## 二、找到插件

企业微信是**官方插件**，随静静一起安装和更新，不用另外下载：设置 → 任务来源 → 官方 →「企业微信智能机器人」。默认停用，点进详情填配置再启用。

> 维护者：插件源码在 `plugin-src/wecom/`，依赖 `@wecom/aibot-node-sdk`。改完运行 `npm run plugins:build -- wecom`，把单文件产物打包到 `plugins/wecom/`，连同源码一起提交（CI 会检查产物是否最新）。

## 三、配置并启用

1. 填 **BotID**、**Secret**；
2. 点「保存配置」，再打开启用开关；
3. 启用后静静会建立长连接，状态应显示「长连接已启动」；
4. 在同一页的「在企业微信里怎么回话」里设：
   - **收到消息先回执**（默认开）；
   - **任务状态播报**：不播报 / 关键节点（等拍板、做完、失败，默认）/ 关键节点 + 实时进度；
   - **能在群里拍板的人**：填你自己的企微 userid（多个用逗号分隔）。默认没有人，群里谁点拍板卡片都不算数；
   - 上面的「任务完成后自动发回原会话」决定结果要不要直接发进群里（默认关，做完只说一句「做完了，结果等主人看过再发」）。

这些都是静静的设置，不在插件配置里：说什么、什么时候说、谁能拍板由静静决定，插件只负责在企微里怎么显示。

连接失败会显示在卡片底部，常见原因：

- BotID/Secret 复制错；
- 机器人没有开启 API 模式；
- 主机网络无法访问 `openws.work.weixin.qq.com`；
- 机器人可见范围不包含发送者。

## 四、使用

在群里：

```
@静静 登录页点提交没反应，帮忙看下
```

静静会把这条消息转成条目：

- `externalId`：企业微信 `msgid`，重复回调不会重复建任务；
- 标题：`企微群消息 · <userid>`；
- 内容：消息正文（有引用时带上引用）；
- 元数据：chatid、chattype、userid。

然后走正常的判断：需要行动就建任务，不需要就不打扰。任务可以通过调度器派给 Claude Code，也可以在任务板里手动处理。

## 在企微里会看到什么

一条 `@静静` 的消息，静静在企微里的回话尽量落在**同一个气泡**上（流式回复，引用原消息，原地刷新）：

1. 马上回「收到，正在看…」；
2. 判断完在同一个气泡里改成：`收到，建了任务「…」，交给「…」去做` / `收到，合并到了已有的任务「…」` / `看过了，这条先不动：理由`；闲聊就直接是静静的回复；
3. 建了任务的话气泡先不结束：开了实时进度会刷新「正在做：…」，做完或失败时在同一个气泡里说完；
4. 需要拍板时，气泡结束，另推一张**按钮卡片**。主人（「能在群里拍板的人」）点了就生效，卡片改成「张三 选了：…」；别人点只会在他自己那里显示「只有主人能在这里拍板」，任务不动；
5. 气泡已经结束或挂得太久（按 5 分钟算），之后的话改成另发一条新消息（不引用原消息）；只想原地刷新的进度这时就不发了。

时间线（任务详情）里会记下每次在企微里说了什么、谁点了卡片、谁想点但不在名单里（带他的 userid，填进名单就行）。

## 能看到静静怎么判断吗

能，但看到的是**判断摘要**，不是模型的原始思维链：

1. 回执里会写判断结果和理由（见上一节）；
2. Web 端「设置 → 任务来源 → 企业微信 → 最近处理」会保留最近 20 条消息的标题、时间、判断结果和理由，可以直接点「看任务」；
4. 任务详情里的「判断理由」也会写进交给 Worker 的指令。

回执只表示“收到并已交给静静”，不代表代码已经修好。

## 测试群验证清单

在测试群里按顺序试一遍，每一步看企微和静静的任务时间线：

1. `@静静 帮我整理一下今天的会议要点` → 一个气泡从「收到，正在看…」变成「收到，建了任务…」，做完时同一个气泡变成「…做完了」；
2. 把状态播报改成「关键节点 + 实时进度」再发一条 → 气泡里能看到「正在做：…」刷新（至少隔 10 秒一次）；
3. `@静静 看下仓库里登录页的 bug` → 气泡说要等主人决定，另推一张「交给谁」的卡片；
4. 「能在群里拍板的人」留空时点卡片 → 卡片只对你显示「还没设置谁能在这里拍板…（你的 userid）」，时间线记下 userid；
5. 把这个 userid 填进去，再推一张卡片点一次 → 卡片变成「… 选了：…」，任务继续；
6. 让一个任务跑超过 5 分钟 → 做完时不再改原来的气泡，而是另发一条；
7. 打开「任务完成后自动发回」→ 做完直接把结果发进群里；超长结果会截断并提示在静静里看全文；
8. 私聊机器人说句闲聊（需开自动发回）→ 回执气泡直接变成静静的回复。

需要实测确认的：流式气泡最长能挂多久（目前按 5 分钟算）、主动发消息的频率限制、markdown 长度上限（目前按 4000 字节截断）。

## 五、限制

- 只处理**文本消息**；图片、语音、文件会忽略；
- 只接收机器人被 `@` 的群消息和发给机器人的单聊消息；
- 长连接断开后 SDK 会自动重连，重连期间消息可能延迟；
- 回复频率受企业微信限制（单会话 30 条/分钟、1000 条/小时）；
- Secret 存在本机 SQLite，界面打码，但不是加密存储；
- 插件依赖官方 `@wecom/aibot-node-sdk`，已一起打进插件的单文件产物。

## 六、重新构建（维护者）

插件源码在 `plugin-src/wecom/`，改完后在仓库根目录运行：

```bash
npm run plugins:build -- wecom
```

产物会写到 `plugins/wecom/`（含这份 README），连同源码一起提交；CI 的 `npm run plugins:check-built` 会检查产物是否最新。
